# data-monitor：监控职责分工执法器

## 定位（先读）

- 本 skill 是**流程执法器 + 指针**，不是第二事实源。职责分工、判据数值、执行状态都在正典
  `docs/data-platform-handbook.md` **§1.5.3**（下称「分工节」）与 §1.5.2（判据-节奏对齐表）；
  本文件只负责「**别跳步、别越界**」。
- 正典与本 skill 冲突时**正典赢**，并回来改本文件。
- **为什么有本 skill**：监控职责讨论过多轮均未执行到底（「经 OO 转投」停在 0 规则、悬空 webhook）。
  2026-10-10 用户定案三层分工（OO=预警面 / openship=基础设施+看门狗 / 数据面=判据本体），
  本 skill 的存在意义 = **这次不再烂尾**。
- 执行追踪唯一 issue：#538（Phase 0/1/2 清单）；分工节执行状态表与它同步。

## 第 0 步：开工三查（顺序固定，缺一不动手）

1. **读分工节**：正典 §1.5.3 三层职责表 + 红线——先确认手头这件事**归哪层、不归哪层**。
2. **查执行状态**：分工节执行状态表（与 #538 同步）——当前处于哪个 Phase：
   - Phase 0/1 未完成前，**openship 现有通知一律不拆**（双通道并行是有意设计，不是欠账）；
   - 状态表说「未开工」的事，做了要**回写状态 + issue 勾选**，不许只做不管账。
3. **查经验库**：WeKnora 检索 OO 告警 / 企微投递 / duckle 观测先例（已知相关条目：duckle L1
   观测/告警面实测、告警静默失效三周）——命中读完整条目再动手。

## 场景判停清单（按手头的事对号，有勾不掉的停在原地）

### 场景 A：新增采集管线（含旧管线改链路）

- [ ] 管线**每次 run 吐一行结果事件**进 OO runs 流：`pipeline_id / org / run_id / status / bizday / rows / ts`（L0 管线绕 #414 sink 缺陷的方案**先实测再固化**，别直接抄 tick 的写法）
- [ ] 事件行缺位 = 管线**没做完**——「采集绿但没人知道它绿/红」不算交付
- [ ] **判停**：事件行进 OO 且能查到，才进下一段

### 场景 B：新增发布面（或给旧面补判据）

- [ ] §1.5.2 对齐表**先加行**：采集滞后（T-N）→ 物化时刻 → 发布时刻 → 容差 → 探活项
- [ ] 容差按对齐表算（**≥ 采集滞后 + 发布周期**，或按时段感知），**不许拍天数**（#534 教训）
- [ ] 探活脚本加断言 + **判红行吐进 OO probes 流**（逐断言一行，带容差线值）
- [ ] OO 规则消费判红行（阈值/缺席），**不是**在 OO SQL 里重写判据
- [ ] **判停**：人为制造一次红（变异），OO 规则真的通知到企微，才算通

### 场景 C：配告警 / 改通知通道

- [ ] **告警单出口**：数据面告警只从 OO 出（企微）；openship 通知只留基础设施与 job 崩溃级
- [ ] 新 OO 规则的容差/缺席窗口**必须引用 §1.5.2 对齐表**的行，规则描述里写明出处
- [ ] 红线自查：OO 规则里**没有**对账 SQL / 库凭据 / 容器操作（OO 是预警面，不是探测器）
- [ ] 每条告警路径都有**反向测试**（人为触发一次真红）+ 看门狗覆盖（OO 自身闪断有人盯）
- [ ] **判停**：反向测试证据落 issue，静默失效路径不存在，才准合

### 场景 D：动 openship job 的通知 / 注册新 job

- [ ] 先问一句：这个 job 的失败**语义上属于谁**？基础设施/job 崩溃 → openship 通知；数据判据 → 数据面吐行 + OO 规则，**别把语义判据塞回 openship 通知**
- [ ] 新 job 命令保持**薄壳**（逻辑在仓内脚本、经 lemeng-sync 落机），多账套场景走**循环收敛**（账套清单进仓），**不许按租户复制 job 副本**
- [ ] **判停**：job 清单相对上一版无未登记的增量（或增量已登记进正典），才准合

## 四条红线（违反任何一条 = 不许合并）

1. **OO 不写对账/新鲜度语义**——它只消费数据面吐出的判红结论（阈值/缺席规则）。
2. **新管线/新发布面必带三件套**：事件行 + 对齐表行 + OO 规则（或登记豁免 + 指明兜底路径）。
3. **告警单出口**：企微通道归一；openship 只出基础设施与 job 崩溃级。
4. **任何告警组件不许静默失效**：看门狗盯 OO，OO 规则缺席/超龄不发按**故障**算，不按「还没配」算。

## 边界

- Phase 0/1 的实测细节（流布局、中继、L0 绕缺陷方案）**未验证前只进 issue/待沉淀，不进正典条文**；
  验证过一条固化一条（无案例不立标准同样约束本 skill）。
- 公司级化触发：第二个项目接入数据面监控时，把三层职责骨架抽到 team-harness（同 collect-source 的
  公司化条款）。
