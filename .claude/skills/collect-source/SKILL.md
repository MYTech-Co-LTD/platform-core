# collect-source：采集接源流程执法器

## 定位（先读）

- 本 skill 是**流程执法器 + 指针**，不是第二事实源。所有判据数值、台账、案例、脚本路径都在正典
  `docs/data-platform-handbook.md`（下称「正典」）；本文件只负责「**别跳步**」。
- 正典与本 skill 冲突时**正典赢**，并回来改本文件（正典更新不同步本文件 = 本 skill 的缺陷）。
- **验证射程**：A→I 目前只在乐檬一族源上完整跑通（含多账套、独立通道、退役半步案例）。
  接乐檬以外源族时，未验环节**必须当场跑最小验证动作**，不许引用乐檬结论代替。
- **公司化触发条件**（任一发生，把 A→I 骨架抽到 team-harness 公司级分发，项目细节留项目层）：
  1. 第二个项目真实接入采集源（候选：data-platform-scaffold 工单系统）；
  2. 或公司标准 data-platform.md（team-harness PR #79）合入。
  在此之前本 skill 是**项目级**资产，别当公司标准引用。

## 第 0 步：开工三查（顺序固定，缺一不开工）

1. **查台账**：正典 §1.7（逐源决策登记）+ §2（数据源清单）里**先找这个源的登记行**。
   - 已有行 → 从登记行标注的状态**续走**，不重跑已过的段；
   - 没有行 → 从 A 段开始，B 段定案时补登记。
2. **查经验库**：WeKnora（`wiki.hookflow.cn`）按源名/厂商/接口检索——先查再动手，命中读完整条目再复用结论。
3. **读正典**：§0（管什么）+ §1.1（决策层，含 §1.1.7 标准形态）+ §1.3（A→I SOP 全文）。
   本 skill 的每段判停都指向正典对应小节，判据细则以正典为准。

## A→I 生命周期：逐段判停（不过不进下段）

> 用法：每段做完，把该段验收锚逐条勾掉；**有勾不掉的，停在该段**，把卡点写进任务报告，
> 不带病进下一段。正典 §1.3 对应小节是每段的完整说明书。

### A 摸清源 → §1.3.1

- [ ] 探针四条全跑（§1.3.1：真实值 / 能力反问 / 跨度上限 / whoami 级主体），交付物落在任务目录
- [ ] 分区键名、页参数、鉴权方式写进探针结论（后续 C/D 段直接引用）
- [ ] **判停**：探针没跑完就写码 = 最贵跳步。正典已记着这个教训，别复刻。

### B 选型定案 → §1.1 / §1.7

- [ ] 走正典 §1.1 决策层（duckle 原生首选分档 → 我方兜底），标准形态对齐 §1.1.7
- [ ] 例外路线（不用标准形态）**必须带证据**在 §1.7 登记，写清为什么不走标准
- [ ] **判停**：§1.7 里没有这个源的登记行 = B 没完成。

### C 契约 → §1.3 对应小节

- [ ] 双轨同改：`contracts/`（湖列集唯一事实源）+ 管线内 `data.schema` 申报，**两处一致**；
      只改投影 SQL 不改申报 = 空页才炸的暗雷
- [ ] `qa.contract` 断言同步改；drift 断言**先钉「声明的字段必须存在」**
- [ ] 改列集跑生成器（正典 §1.2 B10：改契约一处 + 跑生成器，生成物必须 == 已提交），**不手改投影文件**
- [ ] ⚠️ 未验：drift 的**远端形态**（真实源字段增删/改名时的表现）尚无首用案例——
      首个真实漂移发生时当场记录并回填正典，不许引用乐檬结论。

### D 管线 → §1.3 对应小节 + §1.6 案例库

- [ ] 管线 JSON 由真引擎产出并**提交进仓**（口径：仓内文件 = 引擎所写的，不手编）
- [ ] 分页配置**成对检查**：页参数与翻页机制同在——缺一边 = 静默只取首页，
      validate 与 run 都报 ok（案例库有实测记录）
- [ ] schema 申报与投影列集一致；空响应按申报构造，缺申报 = 空页运行时才炸
- [ ] ⚠️ 未验：`xf.tumble`（翻窗聚合）与管线内 `qa.*` 节点组合尚无生产案例——
      首用时当场跑最小验证并回填。

### E 调度 → §1.3 对应小节 + §1.5

- [ ] 调度归口：走 duckle console 管线自身的 schedules，**不另立旁路 cron**
- [ ] 一条 pipeline 只在一侧（console 或 CLI）维护，别两头改
- [ ] 改管线定义走两步：先改文件再让引擎重载（bind-mount 钉的是 inode，
      只写文件不重载 = 跑的还是旧定义，案例库有实测）
- [ ] 排班（几点评/错峰）**如实入账**：正典 §2 台账行 + openship job 记录对得上
- [ ] ⚠️ console 的 `schedules.json` 会被引擎回写（run 状态等），判漂移看**条目集合与 enabled**，
      不看文件哈希。

### F 验收 → §1.4 / §1.4.1

- [ ] 四层验收（正典 §1.4）逐层过，**缺一层不算过**；判据落位按 §1.4.1
- [ ] 管线内的闸只判「不可能错」的断言（不可能 = 断言错了管线就该拒写湖）
- [ ] 自证类检查没过 → 拒写湖是**正确行为**，别绕闸；闸静默放行才是事故
- [ ] ⚠️ 跨系统验收层（下游 BI/报表）目前全部「待回填」，按正典标注的口径处理。

### G 运维 → §1.5

- [ ] 告警可达、能响应、能恢复：探活盯防覆盖本源的调度与新鲜度锚
- [ ] 新鲜度锚验过「匹配到」（catalog 命名得到），不是只配了没生效
- [ ] ⚠️ 未验：告警的**群侧投递与冷却重报**行为——首次真实触发时当场目视并回填。

### H 回填 → §1.3 对应小节

- [ ] 回填走**同一条管线换时间窗**，不另写一次性脚本
- [ ] 逐日对账：回填区间逐日与源对平，残差按正典口径记录
- [ ] ⚠️ 未验：duckle 原生 `/api/backfills` + watermarks 指针式回填——首用时当场跑最小验证。

### I 退役 → §1.6 案例库（退役半步案例）+ §7

- [ ] 三步门槛齐备才动：① 替代通道已建且对账平 ② 消费面全部切走 ③ 观察期过
- [ ] 下线只摘前缀/停调度，**物化不删**（半步案例的口径，正典写明「别照抄」——完整退役
      尚无案例，首例做全时回填 §7）
- [ ] **判停**：三门槛缺一 = 不退役，先补缺口。

## 升级条款（什么时候不许直接照流程走）

出现下列任一，**先 brainstorming + spec 定案（人同意 → 改架构文档 → 再写码），再按本流程逐源执行**：

- 新的**通道类型**（非 duckle 原生也非标准形态的新接入方式）
- 新的**数据域**（采集对象换了业务语义大类，不只换源）
- **多源联动**（一个任务要同时接多个源并保持一致性）
- 触及**架构级**改动（湖布局/物化策略/权限模型）

逐源任务本身仍按「规划先行」落盘 plan 再开工——本 skill 不替代规划，只执法。

## 收尾义务（任务结束才算完成）

1. 正典三处登记：§1.7（决策行）、§2（数据源清单行）、§5（验收记录行）——缺一处 = 任务没完。
2. 新踩的坑进 §1.6 案例库（**只增不改**；订正旧案例另走勘正记录）。
3. WeKnora 沉淀：先查重，命中则更新原条目，不新建。

## 红线

- 本文件**不出现任何判据数值**（容差/阈值/时长/页大小）——数值只有正典与 spec 两个家。
- 未验环节**不许引用乐檬结论代替当场验证**——这是「无案例不立标准」在采集流程上的直接落点。
- 正典与本 skill 冲突 → 正典赢，并当场回来改本文件。
