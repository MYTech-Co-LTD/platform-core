# 报表 IR v2（datasets / blocks / shared filters）——实施计划

> 路线图：`docs/superpowers/plans/2026-11-13-report-platform-roadmap.md` §6 R3。
> 本文件只回答「**怎么做**」；为什么与边界见路线图 §5/§7。**开工前先读路线图台账**。

## §1 目标（可判定）

1. **数据集只声明一次**：同一 `metricId + dims + args` 被多个面板使用时，从重复声明变为 `datasets[]` + 块引用。
2. **共享筛选**：`filters` 在报表级声明一次，块可声明「不参与」（`ignoreFilters`），不再靠每个面板各写 args。
3. **块模型**：`blocks[]` 承载呈现（kpi / chart / table / text / ai_text），与取数解耦；为后续 6 组件与多页留位。
4. **完全向后兼容**：存量 v1（`panels[]`）继续可读、可发布、可回滚；渲染结果**逐字节**等价。
5. **单一执行计划**：渲染与 facts 都从同一份规范化后的 plan 取数（R0 的 `ReportPlan` 落点）。

## §2 数据模型（v2）

```ts
interface ReportSpecV2 {
  ir: 2
  period?: PeriodSpec
  filters?: Array<{ key: string; column: string; label: string; type: 'string'|'number'|'date_range' }>
  datasets: Array<{
    key: string            // 报表内唯一，如 'sales'
    metricId: string
    dims?: string[]
    args?: Record<string, unknown>
    timeScoped?: boolean   // 缺省 true
  }>
  blocks: Array<
    | { type: 'kpi'; dataset: string; title: string; format: ...; compare?: ...; span?: number; goodDirection?: ... }
    | { type: 'chart'; chart: 'line'|'bar'; dataset: string; title: string; slice?: ...; compare?: ...; span?: number }
    | { type: 'table'; dataset: string; title: string; columns?: string[]; dims?: string[]; span?: number }
    | { type: 'text'; title?: string; content: string; format?: 'plain'|'markdown'; span?: number }
    | { type: 'ai_text'; title?: string; focus: 'overview'|'root_cause'|'daily_review'; dataset?: string; span?: number }
  >
}
```

**判别**：`'ir' in spec && spec.ir === 2` ⇒ v2；否则按 v1 `panels[]` 解析。两者**不混用**（同一份 spec 里同时出现 `panels`/`blocks` ⇒ INVALID_SPEC）。

**索引语义**：`blocks[i]` 的 `i` 就是对外 `panelIndex`（叙事缓存键、审计、前端 `data-panel-index` 全部沿用），不因数据集拆分而改变。

## §3 规范化层（唯一入口）

新增 `domain/report-plan.ts`：

```ts
export interface ReportPlan {
  period: PeriodSpec | null
  filters: FilterDef[]
  datasets: Array<{ key: string; metricId: string; dims: string[]; args: Record<string, unknown>; timeScoped: boolean }>
  panels: Array<{ index: number; kind: ...; datasetKey: string | null; ... }>  // 与 blocks 一一对应
}
export function toReportPlan(spec: ReportSpecV1 | ReportSpecV2): ReportPlan
```

- **v1 → plan**：每个 panel 生成一个匿名数据集（key=`p${index}`），args/dims 原样搬入；行为与现状逐字节一致。
- **v2 → plan**：数据集按 key 查；块上的 `slice`/`format` 等呈现字段原样保留。
- **渲染 / facts / lint / 审阅** 只消费 `ReportPlan`，不再直接读 `panels`。
- `parseReportSpec` 增加 v2 分支并返回 `ReportPlan` 可直接消费的判别联合；**旧调用点零改动**（保留返回 `spec` 字段，类型拓宽）。

## §4 分期与出口判据

| 步 | 内容 | 出口判据 |
|---|---|---|
| **V0** | `report-plan.ts` + v1→plan 规范化 + 单测 | 现有 spec 全部规范化后 `toReportPlan(v1)` 字段与逐面板读取一致；`ReportView` 行为不变 |
| **V1** | v2 schema + 解析 + `toReportPlan(v2)` + 发布/写入接受 v2 | v1/v2 各 10 份夹具渲染结果**逐字节等价**（DOM 快照）；发布 v2 成功，回滚仍可读 v1 |
| **V2** | 渲染器（ReportView）改消费 plan；数据集查询去重 | 同一报表的面板查询次数 ≤ 数据集数（R4 缓存之外的结构性去重） |
| **V3** | facts 改消费 plan；`panelIndex` 语义不变 | 叙事缓存键（factsHash/prompt）在 v1 报表上与现状一致（回归集） |
| **V4** | 共享筛选 UI 与 `ignoreFilters`；语义 lint 增加「筛选键必须在 datasets/面板 args 中出现」 | 业务可用一份筛选驱动多块；lint 阻断悬空筛选键 |
| **V5** | console 只写 v2（读仍兼容 v1） | 新建/修订全部产出 v2；库内存量 v1 保持可读 |

> 每一步单独 PR、单独部署；**不允许**一步同时改 schema + 渲染 + facts（回滚面太大）。

## §5 兼容与迁移

- **存量 spec 不迁移**：`data.reports.spec` / `report_versions.spec` 里的 v1 原样保留；读路径规范化。迁移需要批量改写 JSONB，风险高于收益，**不做**。
- **发布**：v1 继续可发布（快照存 v1）；新建/修订在 V5 后写 v2。回滚照旧（读哪版就存哪版）。
- **factsHash**：由 facts 内容决定，不由 spec 结构决定 ⇒ 规范化不得改变面板顺序与索引。
- **MCP / agent**：`propose_report` 的 spec 白名单同时接受 v1/v2；模板编译在 V5 后产出 v2。

## §6 风险与对策

| 风险 | 对策 |
|---|---|
| 规范化改变面板顺序/索引 ⇒ 叙事缓存失效、审计错位 | V0 单测钉「索引 = 数组下标」；V3 用现有叙事回归集验证缓存键 |
| v2 与 v1 渲染不等价 | V1 的 DOM 快照逐字节比对；差异必须解释，不允许「看起来一样」 |
| 双模型并存期写错分支 | `parseReportSpec` 判别唯一：`ir===2` 才算 v2；同时出现两套键 ⇒ INVALID_SPEC |
| 共享筛选改变 args 优先级 | 优先级固定：块 args < dataset args < 报表 filters < 请求时期间覆盖；写测试钉死 |
| 一次性大改导致回滚困难 | V0–V5 分步，每步可独立回滚；V2/V3 出问题时退化为「只读 plan、仍走旧渲染」 |

## §7 明确不做（本计划）

- 不做自由画布；块布局仍由 `span`（24 栅格）表达。
- 不在本计划里加新图表类型（6 组件是 R3 的另一个增量，依赖本计划的块模型）。
- 不迁移存量 spec；不改 `report_versions` 的 append-only 语义。
- 不做跨报表数据集复用（租户级 dataset 库）——等真实需求。
