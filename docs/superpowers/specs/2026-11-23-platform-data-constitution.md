# 平台数据宪法——三平面 · 所有权三分法 · 契约执法换轴 · 事件双轨 · 导出唯一管道（决策记录）

> 状态：✅ **已定（人裁 2026-11-23，全案六条通过）**；**条文即生效，执法面按 §9 落地清单推进**——
> 清单未完成前本文是判准，不是已建成的事实（别照本文假设现状已合规）。
> 性质：宪法级 ADR。它不推翻既有正典，只做三件事：**升格**（把恰好做对的写成规定）、**换轴**
> （把实现选择题换成所有权/版本/声明/执法）、**立新**（分析面单向、导出唯一管道、事件双轨、隔离纵深）。
> 不变量条目已挂 `docs/architecture.md` §4.2。
> 提问原话：「已经有的不代表正确的……项目并没有上线，没有技术债，我要的是方向。」——本文按第一性
> 原理推导后对照现状写成；与现状冲突处，以本文为准并按 §9 排期收敛。

## 1 立宪窗口与前提

前提（决定每一条的强度）：

- **产品未上线、业务数据近零**——这是唯一能把架构写成条文而不付迁移代价的窗口；上线后每一条
  「补写」都是不可逆的债。
- 一个团队、AI 密集开发、多租户（私有化交付为主）、**分析是产品卖点而非附属**（报表/问数/经营洞察）。
- 结论形态在行业坐标系内的位置：**带宪法的模块化单体**——DDD bounded context + published
  language、CQRS 读写分离、transactional outbox、modulith 而非微服务（一个团队上微服务 =
  分布式单体，是最差结局）。

## 2 宪法总纲：一个平台、三个平面

```
┌─ 事务平面（PG，应用单元）──────────────────────────────┐
│ 系统记录。完整性全住这里：约束 / 外键 / 部分唯一索引 / 行锁      │
│ 铁律：任何产品分析面永不读它（I1）                              │
├─ 分析平面（湖 + dbt + 语义层，数据单元）──────────────────┤
│ 唯一分析服务面。所有分析事实——外部采集的、平台自产的——经同一条  │
│ 受治理管道进这里。引擎可替换（§7），语义层是接口                  │
├─ 集成平面（契约 + 事件，协议与 SDK）─────────────────────┤
│ 数据复用 = 声明式契约（§4）；业务反应 = 事务性事件（§5）；          │
│ 人类通知只是事件的一个订阅者，不是事件系统本身                      │
└────────────────────────────────────────────────────┘
```

三条平面互不越界的不变量（I1–I3，已挂架构 §4.2 第二档）：

- **I1 分析面单向**：任何产品分析面（报表/问数/月报/指标）**永不读事务平面**；分析消费一律经
  分析平面。灰区如实登记：内部运营分析今天直读 PG（如 demand-mining 读 `askdata_trace` 族）
  属**容忍灰区**——新面不得照抄，存量随立项迁分析平面。
- **I2 模块不直连湖**（既有正典收编成宪法条文）：业务模块与湖之间无合法通路；
  `DATA_WAREHOUSE_URL` 永不下发给业务模块；staging/湖不对业务模块暴露。
- **I3 进湖=导出非双写、管道唯一**：湖副本只能经唯一管道产生（§6）；写路径永远只有 PG 一条。

## 3 所有权三分法（宪法第一条）

**每个数据集恰好一个 owner；消费方只读 owner 的发布物，永不读生产中间态。** owner 按
**系统记录出处**定，不按数据类型定：

| 出处 | owner | 例 |
|---|---|---|
| 外部采集 | 数据面（采集契约托管） | 门店/商品维表（乐檬采集） |
| 平台原生 | 平台共享内核（`platform` schema） | org、账号、权限、`identity_link` |
| 模块原生业务产物 | 所属模块 schema | 花名册（`aftersales.employee`）、审批流（`forms.*`） |

⚠️ **防过度泛化**：「主数据所有权归采集契约」（架构 §2.3）只适用于**采集物**——org/员工是
共享内核、花名册是业务档案，别把「归数据面」当万能答案。三类各有各的消费契约：采集物走
发布快照（§4），共享内核走平台原语（部门门 / identity 服务），模块原生产物要出模块时走
声明面或导出（§6）。

## 4 契约执法面：换轴（宪法第二条）

跨模块数据协作的正确提问**不是「API 还是直连」**（实现选择），而是四元组
**所有权 / 版本 / 声明 / 执法**：

1. **所有权**：谁的数据谁出契约（§3）。
2. **版本**：owner 发布物 **additive-only**；破坏性变更（删列/改型/改名）= 显式登记
   （`dataDependencies` 门禁判据 2 的语义），消费方声明与迁移同步改。
3. **声明**：消费方在 manifest `dataDependencies` 声明依赖集——**声明 = 可读授权**，manifest
   是唯一审计面。
4. **执法**：声明↔实现一致由 B1 判（已落地）；列集变更登记（判据 2）随首个真实声明落地。

传输形状（①同步查询 ②发布快照）**保留为用例判据**，判定三问原样继承（请求路径上吗 /
全量吗 / 容旧吗）。**为什么轴要换**：前缀白名单把 schema 级耦合制度化——owner 改列名，
破坏在运行时才暴露；声明面把破坏提前到构建期。

**待收敛的 seam（如实登记 + 裁决）**：`dataDependencies` 节（module-protocol，2026-09-23）
要求声明物是**稳定视图**（「声明物理表属于违规」），而跨模块 ADR（2026-10-07）形状②的发布物
是**带版本快照表**（`data.dim_*` 即物理表，B1 前缀豁免）——两个正典对「可声明物」不一致。
**裁决：可声明物 = owner 发布物（稳定视图或带版本快照表）**，列集变更登记对两者同等生效；
module-protocol 相应行随首个声明修订。B1 的 `data.dim_*` 前缀豁免在声明集覆盖后退役
（其注释已自认：「声明面出现前的历史通道，收敛后可由声明集替代」）。

## 5 事件双轨（宪法第三条）

- **一个事件骨干，两种保证档**：**通知档**（fail-open、投递给人、返回不参与业务分支——
  AGENTS 硬约束 12 原样）与**反应档**（事务性 outbox、at-least-once、幂等消费）。
- **人类通知是骨干的一个订阅者**，不是骨干本身。今天的 `platform.event_catalog` 长在 notify
  里，语义是通知档——这是**起点不是终态**；SDK 的 event catalog 预留 guarantee 档位扩展点
  （方向条文，未实施）。
- **立项判据（到了才建 outbox，此前不建）**：首次出现「A 模块的状态变化必须触发 B 模块的
  业务动作、且丢失不可容忍」的真实需求。盘点今日全部跨模块协作（读维表 / 导湖 / 通知审批）
  全是读或通知，没有一条业务反应——不预建。
- **红线**：永不把 notify 的 fail-open 弯成业务分支——丢一次事件 = 业务静默断裂。这条诱惑会在
  第一个「审批通过自动开账号」类需求出现时到达，先立此防。

## 6 导出唯一管道（宪法第四条）

- PG 是唯一事实源（系统记录），湖是分析副本；**审计贴着系统记录（PG 同事务），湖不做审计源**。
- **唯一管道五件套**（forms 首例已验证：ADR-0005 §13.1 → `forms-out-lake-m1.4` →
  2026-10-17/18 落盘回迁）：**水位**（`id` bigserial 类）+ **日批** + **键集游标** +
  **契约钉信封**（`layout.partitionBy` / 源 id / bizday；内容保持半结构化按需展开——
  schema-on-read 边界）+ **org 注入**（`subject_org()`，主体列不进湖——共享面翻转条件见
  架构 §4.2）。
- **泛化为 SDK 能力（触发 = 第二个导出数据集立项）**：manifest 声明
  `{export: {dataset, watermark, partitions}}`，宿主统一执行——**管道一条，数据集 N 个**；
  第三个模块不许再抄 bespoke 管线。
- **升级路径（写进方向，不是现在做）**：水位批量 → WAL 逻辑复制（CDC）；信封契约不变，
  只换运输层。触发 = 近实时需求或量级跃迁。
- 灰区登记：内部运营分析直读 PG 的表不构成「导出」，属 I1 容忍灰区；新数据集走管道，别添灰区。

## 7 语义层是引擎替换接口（宪法第五条）

- 分析消费必经 marts/语义层；消费方不得直触引擎特性。
- 现状恰好合规（dbt + marts + askdata 语义层）；本节把「恰好」变「规定」。
- 换引擎的触发（如实登记，不是预测）：askdata 并发上来、租户数涨、单节点内存/窗口吃紧——
  DuckDB 单节点有并发天花板。到那天，**换引擎 = 搬 marts，不是重写产品**——这就是本条的全部价值。

## 8 租户隔离纵深（宪法第六条，趁窗口）

- 第一道（已有）：纪律执法——每查询 org 谓词、每表 org 列（装载期真库对账门禁）。
- **第二道（本宪法新增，窗口内做）**：全量 SQL lint 强制 org 谓词（先做：成本低、无运行时
  开销）；RLS（`current_setting('app.org')` + 池中间件注入）留作**升级档**——触发 = 租户数
  增长或出现跨租户事故假设。为什么先 lint：RLS 在单角色/迁移/superuser 绕过上有真实运维
  成本，lint 拿走八成风险的两成成本。
