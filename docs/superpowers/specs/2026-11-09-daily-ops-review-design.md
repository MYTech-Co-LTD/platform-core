## 2 分析模型

### 2.1 时间口径

- **today** = 最近一个已闭营业日（默认；不取当天未结数）。
- 三个基线：
  1. **昨天**（环比日）
  2. **本月至今日均**（MTD 累计 ÷ 已过天数）
  3. **去年同月日均**（去年同月累计 ÷ 同月已过天数；数据不足则明确写「无去年同月数据」）

### 2.2 事实包（DailyOpsBundle）

- **今日快照**：营业额、客单量、客单价、毛利、毛利率、报损、报损率、费用、费用率。
- **对比**：三个基线各自的绝对值、差、差率；每个指标给 `good/bad/neutral`（阈值可配，默认 ±5%）。
- **成本结构**：毛利 − 报损 − 费用 = **净毛利**（固定成本未接入时明确标注「未含房租/水电」）；
  净毛利率；与目标（默认 20%）的差距。
- **MTD**：累计营业额 / 毛利 / 净毛利 / 净毛利率；是否达到目标；缺口金额。
- **驱动**（仅当净毛利率低于目标或环比明显变差时）：
  - 销售侧：营业额变化、客单量变化、客单价变化；
  - 成本侧：毛利变化（售价/成本）、报损变化、费用变化；
  - Top 贡献：报损原因 Top、费用项目 Top、门店/商品 Top（复用 W6 variance/top_contributors）；
  - 每条结论带证据（金额/项目/维度/数据截至）。
- **建议**：2–3 条，必须绑定一个事实（金额/项目/维度），禁止空话；可给「核对/复盘/调整」类动作。

### 2.3 输出与安全

- LLM 只负责表述；数字必须来自 `facts.numbers`（现有白名单机制）。
- 固定模板作为回退：仍输出「结论/异常/根因/建议」，但内容来自同一事实包，不是写死的一段话。
- 不做外部归因（天气/竞品/促销）；不推测数据外因果。
- 所有取数走 `runQuery` / 既有探针；不新开自由 SQL 通道。

- 不在 P1 之前承诺「今天毛利」可用（item_profit 日更未追上）；
- 不做跨租户共享。
