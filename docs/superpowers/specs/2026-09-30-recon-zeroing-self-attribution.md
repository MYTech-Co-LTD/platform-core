> 1. **「退货按原单销售日冲减」是错的**：平台 `itemsales` 的 `sale_money` **不冲减退货单**
>    （`order_transaction_type <> 'SALE_ORDER'` 的单本来就不进它的口径）。正确的是
>    **只把换货单的「送出半边」计入**：`(Σ非赠品行额 + order_total_money) / 2`
>    （等价换货=Σ/2；差价换货=(Σ+总额)/2）。同一张 `SALE_ORDER` 里也可能装着换货的退回行。
> 2. **本文件 §3 自述的边界（「验证日只有一个」）没有被遵守**：结论写成了

## 0. 两个判别式（本次的产出）

### 赠品判别式（`gift`）

```
state='FINISHED'
AND order_detail_std_price > 0 AND sale_money > 0 AND quantity > 0   ← 护栏（退化命中排除）
AND abs(discount_money − order_detail_std_price × quantity) ≤ 0.02
```

**语义**：折让 = **标准价全额 × 数量** ⇒ 该行分文未收（白送）。
对照组（普通折让行）：`discount_money = (std_price − price) × quantity`（降价差）——实测店 15/28 的已知假阳性行逐分符合此式，**不落入**赠品判别式。

### 退货归零（`return(D)`，按原单销售日归属）

```
state='FINISHED' AND order_transaction_type != 'SALE_ORDER'
AND order_ref_billno → 原单的 bizday = D        ← 用 order_ref_billno join 回湖
```

**语义**：平台报表日 D 的 `return_money` = **原单销售日为 D** 的退货（与退货何时发生无关）。

## 2. 归零后的对账公式（S2 断言的收紧口径）

```
对每个 (店,商品)：
lake_net = Σ sale_money − Σ gift 行的 sale_money − Σ return(D) 行的 sale_money
gap = 平台 sale_money − (lake_net − 平台 share_discount 对应项)
判据：|gap| < 0.5 且 gap 只允许落在「gift/return 命中项」上
```

（与报告 §3 末的结论一致，但从「有名有姓的排除项」升级为「**湖侧可复算**」。）

## 3. 边界与诚实清单

- **验证日只有一个**（09-27 有平台真值标签）。跨日只验了「形状与量级」，未对平台逐日复算——若要逐日对账，需按归因脚本的报表端点逐日拉平台数据（凭据面已有）。
- 赠品判别式的**机理**是推断（折让=标准价全额 ⇒ 白送），经一天真值 21/21 + 假阳性对照 + 跨日形状三重支撑，但乐檬未确认——若上游促销规则存在「非赠品但全额折让」的场景，会在别的日子引入误报（当前 8 天未见）。
- `order_ref_billno` 归属依赖 join 回湖（原单必须也在湖里）；跨对账期最早的几天若原单在湖外，归属会缺——当前对账日不受影响。
- 回填后的 09-23~09-27 分区**不包含**「原单日更早、退货更晚」之外的任何变化；退货行落在其**发生日**分区（如 09-27 的退货在 09-27 分区），归零公式用 ref 归属，与分区无关。
