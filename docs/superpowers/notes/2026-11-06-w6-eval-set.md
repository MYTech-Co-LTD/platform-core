## 3. 确认办法（人来裁决，agent 不代签）

1. 逐条判断：**这条问法业务上真的会问吗？** 不会 → 划掉（写明理由）。
2. 会问的，确认**期望指标**与**时间窗口径**（截止到昨天还是含今天、按哪个时区）。
3. 把确认结果改成 `已确认` 段（保留原表，移动行而非删除——审计要能看出被否过什么）。
4. 达到 50 条后跑入库（`decided_by` 必填），再跑 `verify-regression.mjs`。
5. 回归全绿 + 锚点对账 100% 后，W6 出口判据 ①③ 才算满足。

## 4. 已知边界

- `metric_hunt` 的 target 形如 `<session>|<from>..<to>`，是「同会话同时间窗查了 ≥2 个指标」的分组键，**不是指标名**——不要按指标名解读。
- 26 条 `rejected` 里多数是文档/指令/网关中断，不是「问错了」，保留是为了让「为什么不算数」可追溯。
