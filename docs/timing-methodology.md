# 时序设计方法论（采集与物化的相位）

> **它解决什么**：这条线最贵的一类缺陷是**相位撞车**——读正在被重写的湖分区 ⇒ ETag 失败 / 读到半截 /
> 覆盖写腰斩（正典 §1.6 案例 20/22/37/40）。我们过去的修法一直是**把某个 job 挪个时间**：
> `windows.l1` 挪 08:50、对账档挪 03:30、审计上界改 T-3。**每个都对，但都没留下推导**——
> 上游一变（采集窗口、lookback、主档超时）就全部失配，且没有任何东西提醒。
>
> 本文给一套**可执行的推导与固化**办法，把「拍时刻」换成「算时刻」。
>
> 相关：`docs/collection-tutorial.md`（带案例的入门）、`docs/data-platform-handbook.md` §1.5.2（判据-节奏对齐表）、
> `scripts/lemeng/data-lanes.json`（车道声明）、`scripts/lemeng/phase-audit.mjs`（门禁）。

---

## 0. 一句话

> **相位不是「安排」出来的，是「推导」出来的。**
> 每个 job 的时间点都应当是上游参数的一个函数；只要还允许人拍一个数字，那个数字迟早会过期。

---

## 1. 四步法

### ① 测源端三参数（**不许取单次观测**）

每个数据源都要有三个参数，缺一个就没法推导下游：

| 参数 | 定义 | 怎么测 | 现状 |
|---|---|---|---|
| **发布滞后** | 源端 T 日的数据，到 T+n 小时才稳定 | 探针连续跑 N 天，取 **p50 / p95 / max 分布**（不是单次） | SLA 在测（`data.sla_measure`） |
| **可变窗口** | 距今天几天以内，这个源还会被**整天重写** | 对比「首采」与「次日重采」的差异行占比 | ⚠️ **靠人声明，尚未测**（见 §4） |
| **节奏** | 采集/写入的节拍 | 排班 cron | 声明在 console `schedules/*.json` |

**为什么必须取分布**：案例 27 —— 契约写「T-1 有数据」，实测恰好相反（发布滞后 16–46h）。
**一次探针定不了窗口语义**，因为发布滞后本身是重尾分布。

### ② 推导相位（写死成声明，不许手调）

> ⚠️ **相位是两维的：采哪天（日）＋ 采几次（频率）。** 只推前者是这次复盘补上的盲区。
> 频率同样必须由参数决定，不能「反正不贵就多跑几次」：
> - **有新鲜度需求** ⇒ 频率 = 容忍延迟的倒数（10m 车道就是这档）；
> - **无新鲜度需求**（数据已是 T-2 这种陈旧日）、只为抓源端事后修订 ⇒ 频率 = **修订发生率的函数**，
>   而这个发生率**必须先测**（`data.source_day_fingerprint`），不能猜。
> 反例：`inventory.snapshot.l0` 每 **15 次/天** 重采 T-2——T-2 在新鲜度上毫无需求，
> 每小时重写的唯一作用是「持续制造可变面」去换「也许存在的修订」。

| 要算的东西 | 公式 | 落地处 |
|---|---|---|
| 物化起点 | ≥ 源**发布滞后 p95** + 余量 | `data-lanes.json` 的 `startMinuteCst` / `buildOffsetMinutes` |
| 读窗口 | 落在**可变窗口之外**，或在窗口内用**闭窗谓词/热层** | `closed_before_predicate` 宏 |
| 判据容差 | **≥ 采集滞后 + 发布周期** | 正典 §1.5.2 对齐表（**禁止拍天数**，#534 教训） |
| 判据上界 | 只判 **源已定稿**的日子 | `audit_until_date()`（现为 T-3） |

**余量也要算，不许拍**：案例 3 的余量是「(页数−1) × 页容量」算出来的，不是「给两倍保险」。

### ③ 门禁固化（人肉偏移一律失效）

三条互补的门禁，都在 CI：

| 门禁 | 拦什么 |
|---|---|
| `check-data-lanes`（A4/A5） | 增量模型必须恰好属于一条车道；1h 起点必须晚于最后一个采集偏移 |
| **`phase-audit --check`**（#2966） | 读窗口与可变面相交、**且读侧没声明避让手段** ⇒ 红；console 排班未能归类 ⇒ 红 |
| `check-console-schedules` | 排班与管线定义的一致性、时区 |

`phase-audit` 的判据刻意收窄：**有 mitigation 的不算冲突**（闭窗谓词 / 只读封版 / 上界 T-3 都是声明过的设计）。
它拦的是**新债**——新增一个「读 T-1 又不带闭窗谓词」的 job，或把 job 挪进可变面时段。

### ④ 观测回填校准

SLA（`data.sla_measure`）持续测实际 lag；**贴线或成片红 ⇒ 回第 ① 步重测**。
阈值只从观测来：D4 的结论就是「p95 全部低于阈值 ⇒ 维持现值」，而不是「调小一点更好看」。

## 2. 反模式（都真实发生过）

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| **相位躲子弹**：撞了就挪时间 | 上游一变全失配，且没人知道 | 先在 ① 算出可变窗口，再决定挪不挪；挪了就写进声明表 |
| **拍天数当容差** | 容差 < 采集滞后 + 发布周期 ⇒ 结构性假红（#534） | 按对齐表算 |
| **用绝对值判迟到** | 源闲置（夜里没新单）被判成「建落后」，占 84% 的假红（#2899） | 判**方向**：只有 `source > built + 阈值` 才算迟到 |
| **只看分钟不看小时** | `*/10 9-23` 与 08:50 的 job 分钟相同但不会真撞 | 比相位必须叠加小时范围（`phase-audit` 的 ③ 已做） |
| **时区不换算就比** | 平台 job 是 UTC、console 是 CST，差 8 小时 | 先换算再比 |
| **挪了仓里的 seed 就以为生效** | 排班 seed **不更新存量行**（#2792 的夜窗两本 console 从未生效） | 改完必须查 `/api/schedules` 运行态 |

## 3. 现网实例（2026-11-28 实测）

`node scripts/lemeng/phase-audit.mjs`：

```
writers=69  unknown=0  mutable_faces=12  crowded_minutes=7   读侧冲突 0 组
```

**12 条会重写 T-1/T-2 的写者**（子弹本身）：

| 写者 | 重写 | 节拍 |
|---|---|---|
| `inventory.snapshot.l0` + `.catchup`（两账套） | T-0/T-1/T-2 | 每小时 :12 / :35 |
| `retail.windows.l1`（两账套） | T-1/T-2 | 08:50 |
| `retail.close.l1`（两账套） | T-1 | 00:00 |
| **`retail_order_line.daily_sealed.reconcile`** | **T-1** | **每 30 分钟**（:07/:37/:17/:47） |
| `recon.preagg`（两账套） | T-3 | 00:30 / 00:40 |

**读侧冲突 0 组**的含义是「现有避让手段都在生效」（审计上界 T-3 + 闭窗谓词 + 只读封版），
不是「没有问题」——这正是门禁要锁住的性质。

## 4. 已知缺口（别假装完整）

1. **可变窗口已开始测量**（`data.source_day_fingerprint`，CST 01:30）：每日记 T-lagDays.. 的行数指纹，
   同一 `(源,账套,营业日)` 跨观测日的 `rows` 变化即「首采后还改了多少」。
   ✅ v1 已收 `inventory_snapshot`（`lagDays=2`，源端 D+1 22:35 发布 ⇒ 观测窗 T-2 起）；基线已埋（2026-11-28）。
   ⏳ **待 2 个观测日**才能下结论；结论将直接决定 `inventory.snapshot.l0` 的频率（见 §1 ② 的频率维）。
2. **`daily_sealed.reconcile` 每 30 分钟重写 T-1**：目前没有任何读者被判为冲突（因为读 T-1 的都带闭窗谓词），但它本身就是可疑的频率——待评估是否降到每天一次。
3. **门禁覆盖的是「读 vs 写」的相位**，不覆盖「同一分钟多条重活挤在一条机器上」的容量问题（`phase-audit` 的 ② 只报告，不判红）。

## 5. 开工清单

| 要做的事 | 必须先做的 |
|---|---|
| 新增采集源 | 在 `CLASSIFY` 声明可变窗口（否则门禁红）→ console 排班 → 判据/新鲜度锚 |
| 新增物化/审计 job | 声明它读哪几天（`READERS`）→ 若读可变面内，要么用闭窗谓词，要么挪出窗口 |
| 挪任何 job 的时间 | 先跑 `phase-audit` 看冲突 → 挪完把**理由**写进声明表/路线图台账 |
| 改采集窗口 / lookback / 超时 | **这是上游参数变了** ⇒ 按四步法重推下游相位，别只改那一个数 |
