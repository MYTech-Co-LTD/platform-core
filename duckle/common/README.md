# duckle/common/ — 通用管线定义

**放什么**：一个数据源的一张表对应的**管线定义**，文件名 `<源>.<表>.json`。

```
duckle/common/douyin.sku_daily.json     ← 与 contracts/common/douyin.sku_daily.json 同名
```

**四条约定**（细节与理由见上级 `../README.md`，此处只列硬点）：

1. **文件名与契约同名**（`contracts/common/<源>.<表>.json` ↔ 本目录 `<源>.<表>.json`）。
   两者讲同一张表；改名一起改。**同名是刻意设计的耦合可见化**，不是巧合。
2. **一个文件一条管线**，不对多源做「合集文件」。
3. **落盘必须按同名的契约定型**——契约是声明、管线是实现。管线里出现契约没声明的列/类型，
   那是要改契约（走 PR），**不是在管线里就地放宽**。
4. **不放范本文件**。本目录当前**只有本 README**，这是计划的形态而非遗漏：管线 JSON 必须由
   真引擎产出并 `validate` 通过后落仓，理由见 `../README.md` §4。

**⚠️ 本目录内的任何约束当前都没有静态门禁**：`duckle/` 不在 B1/B8/B9 任何扫描面内
（`docs/architecture.md` §2 明写），契约对管线的「按声明落盘」校验**尚不存在校验器**
（`contracts/README.md` §4.3）。在有人把校验器接起来之前，这四条靠评审与自觉。
