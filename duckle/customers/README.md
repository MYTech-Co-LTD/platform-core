# duckle/customers/ — 客户级管线覆盖

**用途**：同一数据源、同一张表，不同客户需要**不同的取数/落盘行为**时，把该客户的管线放这里。

```
duckle/customers/<客户>/<源>.<表>.json
```

**三条纪律**（与 `contracts/customers/README.md` 同构，因为契约与管线是同一个耦合对）：

1. **形态与 `common/` 完全一致**——同一种管线文件格式，**不另立一套**。
2. **只放完整定义，不放补丁**：管线文件是**声明式**的（声明结果，不声明增量）。
   客户级 = 一份完整管线，不是对 `common/` 那份的 diff。**副本与真源分离**：
   客户覆盖面有限时，`common/` 那份仍然是被其他客户使用的真源，**改 `common/` 要连带看客户覆盖**。
3. **`<源>.<表>` 不变**：客户覆盖改的是**行为**（源端点、账套、落盘目标），
   **不改表身份**。需要另一张表 ⇒ 那是新源，进 `common/`。

**⚠️ 本目录当前为空（只有本 README）** —— 是计划的形态，不是遗漏。
**⚠️ 覆盖优先级未定义**（`common/` 与 `customers/<客户>/` 同名文件并存时谁生效）——
依赖第一个真实案例，本任务**不拍这个板**，**别去猜顺序**。

**⚠️ 无静态门禁**：同 `common/README.md` 末尾那条 —— `duckle/` 不在 B1/B8/B9 扫描面内。
